## 服务器日历

独立原型 `/prototype/calendar-reminders`；正式入口 `/app/execution`。

- 可选范围为实际工作时段、工作截止日期、已保存复习日期；每次导出与新订阅地址的范围明确显示。
- 实际工作时段使用 ScheduleBlock 的真实开始和结束；截止日期是单独的一分钟标记，不再把预计 `time_block` 冒充实际工作时段。复习使用最新已完成尝试保存的日期，输出全天事件。
- 时段、截止和复习各有稳定 UID；保留更新时间、序号、取消状态，UTC 时间与本地全天日期分开处理。取消时段、归档学习和明确取消的复习保留取消事件。移除截止日期后该事件不再出现在完整订阅快照中；实际客户端如何刷新移除仍待服务器连接验收。
- `/api/v1/execution/calendar-export` 用当前登录身份导出所选范围，不需要先建立公开订阅。订阅继续使用 HTTPS `PUBLIC_BASE_URL`，范围持久保存，只读凭据独立于登录令牌。重新生成使旧地址失效，撤销与生成串行处理；旧订阅迁移默认仅保留截止范围，不自动扩大读取授权。
- 只读订阅状态可重新读取；原始订阅凭据不回显。日历应用自行决定刷新频率，不承诺实时同步。

日历 HTTP 检查已验证范围筛选、实际导出、地址轮换、旧地址拒绝、撤销与无效空间拒绝。隔离真实 API 导出确认包含本轮学习保存的 `2026-10-31` 复习事件，未夹带答案或原文。未配置服务器域名时明确失败，不生成本机或虚构有效订阅地址。

## 服务器到期提醒

- 新 `push_subscriptions` 记录账户、空间和设备、启停、时区、每天检查时间与安排版本；`reminder_deliveries` 为持久发送队列，保存计划时间、状态、失败、尝试次数与通道接收时间。
- 只有本人勾选并点击开启后，页面才申请通知权限并登记本设备。服务器通道与后台执行未配置时不放行，不显示已经启用。拒绝权限、不支持的浏览器与保存失败均明确显示。
- 后台循环按已保存时区安排每日到期摘要；无到期工作或复习时保持安静。重启后补偿最近 24 小时的安排；旧安排版本和暂停设备不再发送。并发处理使用数据库锁，失败按同一投递标识重试，失效设备凭据停用。发送有超时与次数上限。
- 通过 `pywebpush` 进行标准加密发送，限定受支持浏览器 HTTPS 推送服务，禁止跟随 HTTP 重定向。通知仅携带通用到期计数，不含学习答案、原文或登录令牌。
- `/reminder-sw.js` 接收后台推送，持久记录最近投递标识，并用稳定通知 tag 去重；点击固定打开本站执行页，忽略外部地址。无页面请求也能进行服务器队列处理。
- “推送通道已接收”不代表设备已经显示或本人已看到。网络请求与数据库无法形成跨服务事务；崩溃或不确定回执可能重试，设备侧去重用于减少重复展示，不宣称严格端到端恰好一次。

加密发送使用真实库与虚构接收密钥、替代网络通道验证，没有发送真实通知。服务器重启、并发、失败重试、安静状态、设备登记/重复登记/修改时间/暂停/空间边界已在隔离数据库验证；Service Worker 去重用持久存储替身跨实例验证。权限拒绝与保存失败为独立原型模拟，未代替本人操作系统权限或真实手机投递。
