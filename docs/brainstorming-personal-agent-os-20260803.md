## 产品定位

> 一个持续理解个人目标、知识、工作和行为的 AI Agent 系统，帮助用户规划人生、管理执行、沉淀知识、优化决策，实现个人能力持续进化。

**核心理念：** 不是工具集合，而是一个 Personal Brain——用户不是在用工具，而是在养一个数字分身。

**与现有产品的差异化：**
- vs. Notion/Obsidian：AI 主动推理，不是被动存储
- vs. ChatGPT：持久记忆 + 个人数据 + 主动建议
- vs. Todoist/滴答清单：AI 项目经理，不是待办列表

---

## 产品原则（设计宪法）

| # | 原则 | 说明 |
|---|------|------|
| P-01 | 每天 < 10 分钟 | 所有功能的用户时间投入不得超过此线 |
| P-02 | AI 推理优先 | 能让 AI 推断的，不让用户输入 |
| P-03 | Memory 是心脏 | 所有 Agent 共享 Memory 层，而非独立存储 |
| P-04 | 被理解感 | 每天一个 AI 引用的 Memory 记忆 |
| P-05 | 简化输入 | 一个表情 + 一句话 > 复杂表单 |
| P-06 | 数据即壁垒 | 产品价值 = 使用天数 × 数据深度 |

## 用户画像

### 第一阶段：超级用户（你自己）

| 维度 | 描述 |
|------|------|
| 角色 | 独立开发者 + AI 创业者 |
| 日程 | 多项目并行（GEO + Personal Agent OS + 其他） |
| 痛点 | 事情太多，缺少 AI 规划；缺乏监督；信息过载 |
| 使用动机 | 把自己作为第一个用户，用 6-12 个月验证产品 |
| 成功标准 | 每天打开，持续使用，无负担 |

## MVP 策略（砍需求原则）

> **不做什么：**
> - 复杂知识分类层级（→ 只做标签 + AI 关联）
> - 多工具同步（→ 第一阶段只集成飞书）
> - 独立 Goal 复杂界面（→ 简化拆解）
> - 成就/徽章系统（→ 用里程碑替代）
> - 知识图谱可视化（→ 只在对话中提及）

## 功能详细设计

### Agent 1: Memory Agent（底层基础设施）

#### 核心定位
> 系统的"硬盘"——不是存储聊天记录，而是构建个人知识图谱。

#### 功能列表

**F-M01: 多模态记忆存储**
- 支持记忆类型：情景记忆（经历+时间戳）、语义记忆（知识+概念）、程序记忆（习惯+工作流）、工作记忆（当前上下文）、情绪记忆（情感标注）
- 存储格式：结构化 JSON + 向量化嵌入
- 数据来源：手动输入 + 行为观察 + 外部工具同步

**F-M02: 智能记忆检索**
- 向量检索（语义相似）
- 关键词检索（BM25）
- 图关联检索（知识图谱关系）
- 时间上下文检索（最近 N 天的相关记忆）

**F-M03: 知识图谱引擎**
- 实体识别（人/概念/项目/工具）
- 关系抽取（包含/关联/因果/时序）
- 置信度评分（来源可靠性和时间衰减）
- 自动去重和合并

**F-M04: Memory 健康度检测**
- 覆盖度：核心维度（目标/任务/情绪/知识）是否都有数据
- 新鲜度：数据最后更新时间
- 关联度：知识点之间是否形成网络
- 每周推送 Memory 健康报告

**F-M05: 上下文管理**
- 当前会话上下文窗口（Redis）
- 今日上下文（当天重要事件）
- 长期主题追踪（跨周/月）

#### 数据模型
```
memory_entry:
  - id: UUID
  - user_id: UUID
  - type: enum[episodic/semantic/procedural/working/emotional]
  - content: text
  - embedding: vector(1536)
  - entities: JSON[]      # 提取的实体
  - relations: JSON[]     # 关系
  - tags: text[]
  - source: enum[manual/reflection/task/knowledge/work/system]
  - emotion: enum[positive/neutral/negative]
  - energy_level: int     # 1-10，触发时的能量
  - created_at: timestamp
  - updated_at: timestamp

knowledge_graph_node:
  - id: UUID
  - entity: text
  - entity_type: enum[person/concept/project/tool/topic]
  - properties: JSON
  - created_at: timestamp

knowledge_graph_edge:
  - id: UUID
  - source_id: UUID
  - target_id: UUID
  - relation_type: enum[contains/associates/causes/precedes/similar]
  - weight: float         # 置信度
```

#### MVP 范围（Week 1-2）
- [ ] 记忆写入 API（支持手动输入 + 自动来源标注）
- [ ] 向量检索（pgvector + PostgreSQL JSONB）
- [ ] 简单实体/关系提取（LLM 调用）
- [ ] Memory 健康度仪表板

### Agent 2: Reflection Agent（每日闭环驱动）

#### 核心定位
> 系统的"心跳"——每天两次（晨间启动 + 晚间复盘），形成数据闭环。

#### 功能列表

**F-R01: 晨间启动（每日 8:30 推送）**
- 今日意图设定：输入 1 句话（今天最想完成什么？）
- 能量状态自评：滑动选择 1-10
- AI 推荐今日任务：基于 Goal + Memory + 近期数据，推荐 3 个任务
- 昨日 Memory 引用："你还记得昨天你说过...？"

**F-R02: 日间微复盘（任意时刻）**
- 快速微复盘：做完任何任务，点击"感觉如何？"→ 一个表情 + 一句话
- 情绪波动记录：能量变化时自动提示记录
- 决策捕获：重大决策时一键记录 + 理由
- 灵感捕获：浮动按钮，随时记录想法

**F-R03: 晚间复盘（每日 21:00 提醒）**
- 完成度评分：滑动 0-100%
- 复盘四问（简化版）：

  2. 做错了什么？（输入框，可选）

  4. 今日情绪？（表情选择：😄😐😔🔥）
- AI 一句话总结（基于 Memory）

**F-R04: AI 行为分析**
- 行为模式识别：时间/情绪/任务类型关联分析
- 能力雷达更新：产品/技术/商业/健康/社交 五维评分
- 能量趋势：周维度能量曲线 + 预警
- 目标进度评估：Goal Agent 数据整合

**F-R05: 周期性回顾**
- 周回顾（每周日）：本周主题 + 里程碑 + 下周建议
- 月回顾（每月末）：月度总结 + 趋势 + 目标重校
- 年度回顾（每年）：全年时间轴 + 里程碑 + AI 洞察

**F-R06: 反射性触发**
- 非固定时间，基于能量曲线动态触发
- 能量骤降时 → 简短复盘（1 分钟）
- 完成里程碑 → 成就记录
- 连续 3 天低能量 → AI 关心问候

- [ ] AI 行为分析基础版（周统计）
- [ ] 周期性回顾模板

### Agent 3: Task Agent（执行引擎）

#### 核心定位
> 不是待办列表，而是 AI 项目经理——智能生成、动态排序、能量匹配。

#### 功能列表

**F-T01: 智能任务生成**
- AI 推荐：基于 Goal 拆解 + Memory 历史 + 当日上下文
- 自动生成：目标自动拆解为任务
- 手动录入：快速添加
- 模板任务：重复性任务模板

**F-T02: 每日任务规划**
- Eisenhower Matrix 自动分类
- 优先级排序（AI 推荐顺序）
- 时间块分配（上午/下午/晚上）
- 能量匹配：高能量 → 难任务，低能量 → 机械任务

**F-T03: 任务执行**
- 开始/暂停计时（番茄钟）
- 进度更新（百分比）
- 子任务自动展开
- 分心阻断提示（基于频率学习）

**F-T04: 任务流管理**
- 依赖关系图
- 重复任务模板
- 延迟原因记录（每次推迟必须选原因）
- 阻塞识别与 AI 建议

**F-T05: 执行分析**
- 完成率统计（每日/每周/每月）
- 预估 vs 实际对比
- 时间分布热力图
- 任务类型偏好分析

## Agent 编排设计

### 架构原则
1. **Memory-first**：所有 Agent 共享 Memory 层，而非独立存储
2. **Prompt-based**：不引入复杂 Agent 框架，用 FastAPI + Pydantic 自己搭
3. **Router 路由**：一个 Orchestrator 根据用户意图路由到对应 Agent

### Agent Orchestrator

```
用户输入
    │
    ▼
Intent Router（意图识别）
    │
    ├─ "今天做什么？"     → Task Agent
    ├─ "目标进展如何？"   → Goal Agent
    ├─ "这周做了什么？"   → Reflection Agent
    ├─ "我的知识库里有..." → Knowledge Agent
    ├─ "帮我写周报"       → Work Agent
    └─ [其他]             → Memory Agent（通用问答）
    │
    ▼
对应 Agent 处理（读取 Memory + 调用 LLM）
    │
    ▼
Response（携带 Memory 引用）
```

### Agent 间通信
- Agent 之间通过 Memory 共享上下文，不直接调用
- 每个 Agent 有"读 Memory"和"写 Memory"的权限
- Agent 协作通过 Memory 事件触发（如：Task 完成 → 触发 Reflection 分析）

## 技术架构建议

### 现有架构调整

> 核心调整：从 GrowthPilot 的"场景插件化"架构，转变为"Personal Brain"架构。

**继承：**
- FastAPI + SQLAlchemy 2.0 async（不变）
- PostgreSQL + Redis（不变）
- Taro 4 + React（不变）

**新增：**
- pgvector 扩展（向量检索）
- Memory 层（新的数据模型和服务）
- Agent Orchestrator（路由层）

**简化：**
- 不需要 scenes/ 插件化（Personal Agent OS 是单用户）
- 不需要 compliance_guard（没有交易合规问题）

### Memory 方案选型

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| pgvector + JSONB | 零新增依赖，PostgreSQL 内置 | 向量能力弱于专用 DB | ⭐⭐⭐ **推荐** |
| Qdrant | 专用向量数据库，功能强 | 额外服务，维护成本 | ⭐⭐ |
| Chroma | 简单易用 | 单机，生产环境不推荐 | ⭐ |
| Weaviate | 云原生，功能全 | 复杂度高 | ⭐ |

**建议：pgvector + JSONB**

理由：零新增依赖，PostgreSQL 已有，pgvector 在 16 版本已内置。Memory 数据 + 向量共存于同一 DB，事务一致性有保障。
