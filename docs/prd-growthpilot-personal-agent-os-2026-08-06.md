本阶段补齐健身个人背景、实际努力程度/当时恢复感受与器械。背景按个人持有、单独允许专家读取、版本化保存；已有记录不补造新字段。下一步由服务端核对条件，只在近期反馈与可用器械/时间匹配时提供原训练结构候选，仍由本人决定采用和填写实际情况。

用户可保存未补齐的背景，但必须本人核对；目标、经验、每周可用天数、单次可用分钟、器械、适用情况和限制分别表达，未知保持未知。背景保存不自动授权，使用背景与既有健身记录读取范围均需用户选择。每次活动可填整次努力程度 1–10、当时恢复感受和实际器械；复用结构清空前次努力程度/恢复。本人描述不作为医学筛查或肌肉恢复模型。

服务端给出资料待补齐、限制待核对或有条件沿用三种状态。最近同日多条记录、过旧、器械未填写/不匹配、未知时长、时间超出容量均不补造训练结构；不适/疲劳/很高努力程度或已报告限制先核对。候选只保留已记录重量、组数和次数，并包含训练前核对及活动后反馈条件。目标/经验用于解释背景，不声称已实现目标对应处方、动作替换或多周进阶。

## Executive Summary

### 2026-10-09 交付补充

D0–D3 首个健身场景已交付本地：个人事实/习惯、传统查看、事项内帮助、专家有来源回顾、采用安排及连续实际反馈。健身专家读取与周期回顾默认关闭；本人确认后按日期使用原事实，解读、安排与实际活动分开。此交付不代表其他领域专家、外部应用、设备、系统通知或线上环境已接通；详细验证与下一范围见实现状态和 Sprint。

### 2026-10-08 个人数据与习惯优先的产品定位

**定位：** GrowthPilot 帮助普通人持续记录和查看真实生活、建立适合自己的习惯，再通过 AI 理解数据、学习新能力并改善行动。长期个人数据和习惯是核心，传统记录、明细、日历及趋势与个人专家 Agent 共用同一份事实。用户无需先学会提示词、配置专家或运行复杂任务，就能获得产品价值。

**产品差异：** 持续采集工作与学习之外的实际训练、饮食、睡眠、测量和财务等事件，让用户能回看个人历史，并在需要时得到有依据的帮助。差异应由采集负担、数据质量、查看体验和连续反馈验证，不以其他 Agent 永远无法接入生活数据为前提。

**使用主线：** 选择一件想记录或改善的事 → 留下真实数据 → 用熟悉的页面查看变化 → 在具体困难上得到 AI 帮助 → 按需进入个人专家模式或采用行动建议 → 实际结果继续进入记录。工作正文、学习实践和复盘沿用 C1 基础；C2 的实际产出能力服务这条主线。

#### 普通用户逐步获得 AI 帮助

- 第一层是记录与查看：允许手动记录、编辑、筛选、日历回看及有样本的趋势，不依赖模型成功。首次进入可选择一个领域或习惯，记录一次实际活动；AI 工作空间生成保留为可选路径。
- 第二层是事项内的帮助：提供“整理这条记录”“解释这一段”“给我一个练习”“回顾这段时间”等具体动作。数据范围从当前事项或用户选择继承，用户不必先选择专家或组织提示词。
- 第三层是个人专家与持续协助：工作、学习、健身、饮食、财务及健康记录等模式各自定义所需数据、分析方法、产出和执行能力。用户可直接进入，也可从记录和具体帮助自然进入；这些层次不构成强制解锁流程。
- AI 产出可以是整理候选、解释、练习、成果草稿或有来源的计划。用户实际活动、确认的数据、模型估计和计划分别表达，不把“给出建议”计为习惯完成。

#### 真实生活数据采集与传统查看

- 采集先从少量必要字段、复用上次记录和快速补充开始。语音、图片、文件及设备接入按实际能力逐项交付，保留原始材料和用户纠正入口；尚未接通的方式不显示为可用。
- 发生时间、时区、来源、单位、原始内容、结构化值及确认状态需可追溯。AI 提取是候选值，估计保留估计标记；缺失数据不补成零或凭空生成。
- 各领域保留独立的记录明细、筛选、日历及适用的趋势。Agent 与页面读取同一份已确认事实，AI 解读可返回对应记录和时间范围。
- 习惯记录区分计划、实际发生、本人声明未执行及未知。按用户选择的频率和时段回看，支持中断后继续和调整；不把漏记自动判为失败，不凭打卡次数认定能力或健康效果。
- 生活事实属于个人长期档案，可关联目标、习惯或任务；工作空间引用不产生第二份事实。新增生活数据的专家访问范围由用户选择，不继承旧工作数据授权。

#### 下一阶段验收与交付边界

先以健身记录与现有学习能力验证“可靠采集 → 传统查看 → 事项内 AI 帮助 → 实际反馈”。健身用于验证线下事件，学习用于验证解释、练习和应用；其他领域按需求与数据接入条件扩展。

验收关注首次记录是否顺利、额外维护负担、用户是否主动回看、AI 帮助是否被采用、反馈是否形成连续事实。专家调用次数与模型运行数不作为核心成功指标。新能力先交付可点击原型，再接真实数据；当前生活数据领域、习惯模型及专家渐进体验均为待开发。

本节优先于下文 PRD 3.2 的默认入口、必须 AI 生成首次空间及 C2–C4 的固定执行顺序。既有功能和交付证据保留，具体下一阶段顺序见 Sprint 的 D0–D3。

### 当前产品规划：个人能力平台与持续工作闭环（2026-10-08）

**依据与适用范围：** PRD 3.2 的工作、学习及持续执行能力继续作为基础；入口和优先级服从上节个人数据与习惯定位。任务承载实际内容和时间，学习链接可手动填写，外部应用按真实连接能力执行。以下尚未实现的能力不计入交付状态。

**定位：** GrowthPilot 是帮助一个人持续完成工作、学习新能力并通过复盘调整方向的 AI 个人成长工作台。产品围绕个人的目标、时间、工作内容和成果展开，默认使用“我的空间”，不要求先配置团队、组织、角色或复杂项目管理体系。

**主闭环：** 目标与周期计划 → 有内容的任务工作页 → 安排实际时间 → 人、AI 与已连接应用推进各自步骤 → 保存真实成果和卡点 → 学习应用与复盘 → 调整下一周期计划。数据采集、对话、分析是贯穿这条闭环的能力，用户不需要再维护一套重复的成长数据。

#### 1. 任务是可以继续工作的页面

任务同时承载安排与内容：标题、状态和日期用于组织，正文用于真正做事。借鉴 Notion 的属性与页面内容分离方式，提供轻量编辑能力，不复制其全部数据库和协作功能。参见 [Notion 页面内容官方说明](https://developers.notion.com/guides/data-apis/working-with-page-content)。

- 输入一句“周日完成一篇 AI 学习应用总结”，系统先创建可恢复的工作页，再异步补充建议结构；AI 失败不妨碍用户编辑。
- 工作页包含完成标准、可编辑正文、资料链接、执行步骤、排期、成果及简短复盘。先支持段落、标题、清单、引用、链接和附件指针，编辑自动保存，正文与 AI 产出可恢复、可保留版本。
- 正文是用户的实际工作位置：写文章、整理需求、做学习笔记、记录实验、保存方案。模板按事项提供写作、研究、学习应用、个人项目四类；普通小任务可直接完成，不强迫填写全部内容。
- 每个步骤标明“我来做”“AI 代办”“共同完成”，并关联执行位置。用户负责阅读、练习、判断与最终采用；AI 可在授权范围内整理资料、生成草稿、检查已有内容及更新内部记录；应用负责真实读写其资源。
- 用户可以直接在工作页继续写，也可以转到已绑定的外部文档。成果引用回到同一个任务，避免在多个页面重复登记。
- “打开资料”“生成任务”“日历到点”“AI 已起草”分别表示自己的阶段，不能冒充整项工作已完成。成果完成与步骤验收按事先设定的标准记录。

#### 2. 日历承载真实安排

- 将截止时间与计划工作时间分开。一个任务可以安排多个有开始、结束、时区的时间段，分别记录预计用时、已发生投入与剩余工作。
- 工作提供任务列表和周日历两种视图；今日页展示当天安排，点击时间段直接进入对应工作页。
- 用户设置可工作时段、学习时段和每日容量，AI 根据已知安排提出排期。获准的固定学习时段与内部排期规则可持续执行；冲突、超载及超出规则的改动提出调整建议。
- 连接外部日历后，在授权范围内读取忙闲、创建或更新本产品管理的日程。同步应保留外部 ID、变更来源和同步结果；发生并发修改时提示冲突，不静默覆盖用户的新安排。
- 时间段结束只意味着本次安排已结束。尚未完成时保留内容，估计剩余工作并提出补排建议，不把用完时间自动标为完成。

#### 3. AI 学习保留手动链接，重点放在理解与应用

- 用户可直接填写一个或多个课程、文章、视频、官方文档链接，并说明“希望学会什么”；先保存来源，自动推荐资源不是当前优先级。
- 在能够合法访问内容时，AI 基于原文生成学习提纲、问题和练习；无法读取登录页、付费内容或视频正文时，只保存链接并允许补充摘录，不根据地址虚构内容。
- 学习页连接笔记、疑问、练习、应用任务和复习安排。阅读后的下一步可以是回答一个问题、完成一段练习，或者把知识用于当前工作，而不是只增加进度数字。
- 学习状态表达为“待学 / 学习中 / 待实践 / 已应用”，记录投入、理解证据与应用成果三个不同维度。保留低负担的本人反馈，不用计时或访问链接推断掌握程度。
- 页面计时只表明站内可观测活动；外部阅读的实际投入可以自报，来源清楚标记；未来连接器或浏览器辅助能力提供的观测也必须单独注明口径。
- 周期计划保留学习目标和练习时段；任务暴露的能力缺口可转为学习事项，学习成果可直接进入工作任务与复盘。

#### 4. 应用与插件提供真实执行能力

“收藏链接”“打开软件”“连接账号”“安装扩展”在界面中分别表达。任意网页地址可以成为资源，只有已有适配能力的服务才提供连接或安装流程，不把链接收藏包装成插件。

- 能力入口位于“我的 → 应用与能力”，从任务中也可按需进入。应用卡写清具体用途，如“安排飞书日程”“保存成果到飞书文档”，展示安装/启用、账号连接、权限与运行状态。
- 首个外部适配器选择飞书，优先打通个人日历与指定云文档；飞书任务的镜像同步在相关身份和接口验证后再纳入。Notion 先作为工作页体验参考，真实连接后置。
- 若服务需要安装或发布应用，先走对应服务的安装/配置流程，再授权账号和选定资源。具体账号资格、应用类型、发布和管理员要求须在接入阶段验证，不承诺所有个人账号都能一键连接。
- 连接后，用户可以把某个任务绑定到指定日历和文档；已授权步骤在后台运行，保存真实日程/文档 ID、结果链接、时间及失败原因。失败可以恢复，重试不会重复创建同一资源。
- 已获准的范围内读写不逐次重复确认；向他人发送消息、公开发布、删除等动作超出任务已有授权时单独确认。用户可暂停运行、撤销连接或缩小资源范围。
- 飞书开放平台提供日历、文档、接口及事件接入等基础能力，但本产品需要自行实现适配与回执，不能因展示应用名称就声称已接通。参见 [飞书开放平台官方介绍](https://www.feishu.cn/hc/zh-CN/articles/950476906644-%E9%A3%9E%E4%B9%A6%E5%BC%80%E6%94%BE%E5%B9%B3%E5%8F%B0%E4%BB%8B%E7%BB%8D)。

#### 5. 计划与复盘持续驱动成长

- 目标定义希望获得的结果或能力，周期计划定义本周重点、学习应用事项与可投入时间；生成计划时同时建立对应工作页及建议排期。
- 晨间只需要检查当天重点与异常；晚间自动汇集当天正文产出、已完成步骤、真实执行回执、学习笔记和阻塞，只补充系统不知道的原因、感受与下一步。
- 周复盘回答“做出了什么、哪些知识用上了、哪里反复卡住、下周怎么改”。结果可回到原任务、学习事项和成果，不只输出一篇泛泛总结。
- 对能力的判断必须关联作品、练习或真实自评；不凭任务数、学习时长生成精确能力分数。
- 调整计划可以修改未完成步骤、时间和优先级，保留已完成成果、历史版本与调整原因。用户已允许的轻量排期规则可自动生效，改变目标、增加承诺或显著改动学习方向时形成可编辑建议。
- 默认只在完成、失败、冲突、授权到期或需要用户判断时提醒。成长回顾按用户设定的节奏产生，不为展示后台活跃而通知。

#### 6. 五个主入口与清晰的页面职责

桌面与手机统一采用 **今日 / 工作 / 学习 / 成长 / 我的**：

1. **今日：** 当天时间线、最多三件重点、继续上次工作、AI 新产出或需要处理的异常；晨间检查与晚间复盘常驻可达。
2. **工作：** 任务和轻量项目，列表/日历视图，任务正文及成果；“进入工作”直接打开内容，不先进入控制面板。
3. **学习：** 链接资料、当前学习、笔记/练习、实践任务、待复习内容。
4. **成长：** 目标、周期计划、日/周复盘、带来源的成长回顾与计划调整。
5. **我的：** 个人偏好、应用与能力、授权、数据管理及历史工具。

Agent 保持全局可达，在任务、学习和复盘内理解当前上下文；记录与分析进入对应事项和成长回顾，不再要求用户先跨越“数据 / Agent / 分析”三个独立首页。执行日志放到任务详情和能力管理中，现有独立执行页作为诊断入口保留。

#### 7. 持续执行的产品合同

- 用户确认任务的范围与代办规则后，服务端按时间、步骤依赖和已接通的外部事件推进，不依赖网页打开、按钮点击或前端轮询。
- 每次运行明确输入、使用的能力、执行状态及实际输出。AI 草稿写入任务或指定文档，不能只有一条“已执行”日志。
- 任务状态与机器运行状态分离。“AI 正在整理”不表示“我正在学习”，“等待我评阅”也不算失败。
- 已完成步骤由真实回执或相应完成标准确认；后续步骤只有在依赖满足时才能继续。关闭网页后后台仍可生成已授权产出，重新打开能继续查看和处理。
- 服务端要支持重启恢复、有限重试、去重、暂停、取消和运行额度；已取消任务或已撤销连接不会继续读写外部资源。
- 新计划不默认继承旧的“自动生成待办”开关为无限工具写入授权。任务范围、资源权限与触发规则须可审阅，确认一次后在该范围内持续执行。

#### 8. 第一版范围与验收示例

按 C0–C4 逐步交付，顺序与验收见 Sprint 文档：先验证五入口和完整工作场景，再交付本产品内的工作内容、日历、学习应用及复盘，然后加入实际 AI 代办和首个外部连接器，最后增强多周期成长调整。

**贯穿场景：“两周学会使用 AI，并完成一份自己的应用方案”。** 用户填写学习链接和每周可用时间；确认后得到学习事项、工作页、完成标准与日历安排。AI 在后台整理可读取资料，并将草稿和练习写入工作页；用户完成阅读、实践及判断。若连接了飞书，时间写入指定日历，方案产出保存到指定文档并回收链接。晚间复盘自动汇集当天成果与阻塞；周复盘提出带依据的计划调整。关闭网页、执行失败、重试、改期和断开连接都有可解释的结果，已完成内容不会丢失或被重复创建。

**个人产品边界：** 保留轻量项目、个人能力、目标与周期复盘；组织架构、团队考核、企业审批、工时考勤、复杂角色权限及插件市场不进入本轮。无需外部账号也能完成本地工作与学习闭环。

**当前基础与缺口：** 当前已有可持久化任务、个人 Agent、事实分析、计划后台生成下一项待办、学习来源链接/站内活动记录以及只读日历订阅。尚缺可持续编辑的任务正文与成果、独立起止时间排期、AI 实际工作产出、飞书真实读写回执和自动汇集后的成长复盘。现有“后台创建任务”只算调度基础，不计为完整执行。

### 历史产品主流程：数据采集、Agent 对话与数据分析（2026-10-07）

该阶段的核心体验由 **数据采集、Agent 对话、数据分析** 组成，相关持久化、引用与事实统计合同继续有效；主导航与下一轮交付顺序以 2026-10-08 规划为准。

```text
用户记录或提交资料 / 已发生的行动反馈
    -> 保存原始来源，确认需要结构化的事实
    -> Agent 读取授权范围内的个人数据，结合连续对话理解问题
    -> 返回回答、来源引用和可选择的行动建议
    -> 用户确认后保存记录或创建行动，执行后补充结果
    -> 基于已确认事实计算统计、变化和趋势
    -> Agent 解释分析结果，用户决定下一步
    -> 新的执行结果回到数据采集
```

**三个核心环节的产品合同：**

1. **数据采集：** 用户用一句话记录进展、状态、决策或学习内容，也可以提交文本和网页地址；任务完成、学习进度和晨晚复盘产生行动事实。原始内容、来源、发生时间和保存/同步状态需要可见。语音、图片、文件和外部工具导入作为后续采集渠道，不能展示为当前已支持的能力。记录应先可靠保存，AI 整理失败仍可继续使用。
2. **Agent 对话：** 用户可围绕自己的记录和某个时间范围连续提问，从记录或分析详情直接发起对话。Agent 必须说明使用了哪些事实，支持展开原始来源；对话历史需能恢复。用户可确认把回答中的内容保存为记录、知识、目标、计划或任务。普通聊天和未经确认的 AI 推断不自动成为已发生事实。
3. **数据分析：** 用户按日、周或月回看真实记录、任务执行、学习和复盘的变化。数值由领域事实计算，AI 负责解释和建议；显示时间范围、样本覆盖、计算口径及来源。样本不足时不生成看似完整的趋势。分析详情支持“和 Agent 讨论”，确认后的调整产生新的行动及后续反馈。

**首个端到端验收场景：** 用户记录“今天学习了 30 分钟，但计划中的任务没有完成”，保存后可刷新恢复；向 Agent 问“这周为什么推进不顺”，回答引用本周真实记录，缺少依据时追问；分析页显示实际任务和学习统计，用户从分析进入同一上下文的对话，确认一个调整任务，完成结果又回到记录与下一次分析。所有跨页引用使用同一用户、Workspace 和真实对象 ID。

**A4 已交付口径（2026-10-07）：** 日/周/月使用当前用户时区的自然范围，统计真实完整样本并展示覆盖与原文。实际学习分钟需要显式录入；自由文本数字、预计时长和进度不自动转成投入。任务完成数采用当前仍已完成且最近完成时间落在范围内的口径，当前未完成数明确为状态快照，不伪造历史完成率/趋势。分析进入 Agent 时冻结授权范围与全部来源；确认任务的完成结果回到数据与下一次分析。当前不提供重开/多次完成的执行事件趋势及历史目标进度曲线。

**A5 试用收口（2026-10-07）：** 手机固定展示今日、数据、Agent、分析、我的，桌面侧栏采用同一入口与名称。记录及手机菜单使用原生模态弹层，支持键盘焦点约束、Escape 关闭与焦点返回；Agent 输入区支持 Shift+Enter 换行，并避免中文输入法确认时误发送。云端读取失败或只读到部分数据时明确提示并提供重试。已用隔离数据库和虚构数据完成首次建图、记录、投入、分析、真实 Qwen 对话、确认行动及结果反馈闭环，并覆盖保存成功但响应丢失后的刷新恢复。Sprint A0–A5 开发验收完成；真实环境仍需应用已有迁移并配置后端与模型，实体手机键盘/读屏器及其他手工操作可靠队列仍属后续验收边界。


**平台事实与当前决策（2026-10-07）：** 当前仓库包含 React Web 和 Taro 小程序工程，尚未发现独立 iOS/Android 工程或安装包。用户已明确无需 App 打包，当前按手机浏览器与桌面 Web 推进。每项新能力先交付可点击 UI 原型，再继续实现与验证；手机端是重要的采集与对话使用场景。

GrowthPilot 是一个 **AI Personal Workspace + Growth OS**：以工作台承载用户的工作空间、项目、目录、任务、知识、软件、插件和 Skill，以成长引擎持续理解目标、计划、执行、学习和复盘，并在用户需要时给出下一步和可执行结果。

产品不是“个人资料管理器”、 “Memory 笔记库”或“单一成长教练”。用户通过自然语言描述要做的事，AI 负责理解、拆解、连接上下文、调用合适的工具或 Skill，并把结果沉淀为任务、项目、知识、计划和个人成长数据。用户主要负责确认、调整、执行和反馈。

**产品定位语：** 你的 AI 成长工作台，把想法、工作和成长变成持续推进的行动。

**核心闭环：**

```text
一句话表达 / 捕获资料
    -> AI 理解意图和上下文
    -> 生成或调用 Workspace / Project / Goal / Plan / Task / Knowledge
    -> 用户确认后执行
    -> 工作、学习、复盘事实自动记录
    -> 数据分析目标推进、行为模式和成长变化
    -> AI 生成提醒、回顾和下一步
```

**本次产品校正：**

- 从“Personal Growth OS 作为一组成长模块”升级为“Workspace 作为产品载体，Growth OS 作为智能层”。
- 从“Memory 是用户主要入口”调整为“Memory 是底层长期上下文，默认入口是工作台和行动”。
- 从“Onboarding 生成四个字段”调整为“Onboarding 生成首个工作空间、项目、目标、计划、待办和学习入口”。
- 从“首页展示状态占位”调整为“首页展示当前工作、进行中内容、计划、任务、知识、能力入口和 AI 下一步”。
- 从“交易功能降级后主导航仍偏工具列表”调整为“应用、插件、Skill、历史交易全部纳入可组织的能力层”。

## Product Scope

### MVP In Scope

- Web Workspace Shell：桌面侧边栏、工作空间切换、全局 AI 输入、最近活动和能力入口。
- Workspace 基础版：工作空间、项目、目录/资源指针、最近产出和进行中状态。
- App / Plugin / Skill Registry 基础版：软件入口、已连接应用、插件和 Skill 的发现、启用状态、权限提示和工作空间范围。
- AI Onboarding：一句话生成首个 Workspace、当前项目、一个主要目标、一周计划、最多三个今日任务和一个学习入口。
- Dashboard Command Center：今日简报、进行中项目、任务、成长计划、知识学习、AI 洞察、最近活动和快速入口。
- Goal / Plan / Task Agent 基础版：自然语言创建、AI 拆解、目标关联、完成/推迟/阻塞和基础统计。
- Knowledge / Learning 基础版：内容捕获、AI 摘要、学习队列、目标关联和 Memory 写入。
- Reflection Agent 基础版：晨间启动、日间微记录、晚间复盘和周回顾。
- Memory Agent 基础版：作为所有工作、学习、任务和复盘事件的统一上下文层，支持写入、检索、引用和健康度。
- Global AI：基于 Workspace、Project、Goal、Task、Knowledge 和 Memory 的问答、规划、行动转换和引用。
- Mine：成长数据、工作数据、能力趋势、提醒、集成、权限、导出和隐私设置。

### Out of Scope for MVP

- 自动控制本地电脑和未经授权的文件写入；第一阶段只支持明确授权的目录和应用入口。
- 多 Agent 长时间后台自治和复杂并行编排；先记录 Agent Run 和用户确认链路。
- 多工具全量同步矩阵；优先实现目录指针、常用软件入口和少量连接器。
- 社区、UGC、模板市场和多人协作。
- 成就徽章等强游戏化系统。
- 知识图谱可视化大屏和复杂目录权限。
- 完整交易/投资场景扩展；旧投资功能作为历史工具或垂直插件保留。

## Functional Requirements

### FR-001: 用户启动与个人上下文初始化

**Priority:** Must Have

**Description:**
用户首次进入系统时，用一句自然语言描述当前状态，系统据此建立首个可工作的个人 Workspace，让后续 AI 建议、计划和行动拥有初始依据。

**Acceptance Criteria:**

- [ ] 首次启动支持一句自然语言输入，不要求用户先填写结构化表单。
- [ ] AI 生成当前工作空间、当前项目、一个主要目标、一周计划、最多三个今日任务和一个学习入口。
- [ ] AI 理解结果以“确认 / 修改一句话 / 拒绝”交互呈现，用户不需要逐字段维护。
- [ ] 初始 Workspace、Project、Goal、Plan、Task 和学习入口均可在后续页面调整；个人 Profile 只作为可选底层上下文，不阻塞进入工作台。

## Non-Functional Requirements

### NFR-001: Performance

- Dashboard 首屏数据加载 <= 2 秒。
- Morning / Evening 核心流程提交 <= 1 秒，AI 总结可异步返回。
- Memory 检索 P95 <= 1.5 秒。

### NFR-002: Reliability

- 每日提醒失败时可在用户下次打开时补偿展示。
- AI 生成失败时不阻塞用户保存复盘或任务。
- Memory 写入必须具备幂等保护，避免重复记录。

### NFR-003: Privacy and Security

- 所有用户数据按 user_id 隔离。
- 外部工具集成使用最小权限。
- 敏感配置不得暴露到前端。
- 删除数据后不得继续被 Agent 检索。

### NFR-004: AI Quality

- AI 建议必须引用可追溯的个人上下文。
- 对不确定推断必须降低语气确定性。
- 用户标记为无用的引用应进入后续优化信号。
- 避免泛泛鸡汤式建议。

### NFR-005: Cost Control

- P0 流程优先使用低成本模型。
- 周/月回顾、知识摘要等可异步批处理。
- Memory 检索优先走本地数据库检索，再决定是否调用 LLM。

## Migration From Existing GrowthPilot

### Preserve

- FastAPI + SQLAlchemy async + PostgreSQL + Redis 基础栈。
- Taro 4 / React 前端基础。
- AI Provider、Prompt Loader、LLM Call 记录能力。
- Knowledge 相关已有能力可作为 Knowledge Agent 的雏形。
- Growth engine 中任务、签到、成就的部分能力可拆分复用。
- 已完成的 Memory 写入、搜索、编辑、软删除和撤销能力作为底层数据能力保留，不继续扩展为默认主界面。

### Reposition

- 交易/投资功能从核心主线降级为可选历史模块或未来垂直插件。
- 旧的“增长引导”从交易成长任务重构为全成长任务系统。
- 旧的 AI 教练从交易性格分析重构为个人成长教练。
- 旧的 Onboarding 从 Profile 初始化重构为 Workspace 初始化和首个行动计划生成。

### Replace

- 用 Workspace + Event + Memory 架构替代以 records/scenes 为中心的场景插件架构。
- 用 Reflection Agent 替代旧的交易复盘主线。
- 用 Goal/Plan/Task/Knowledge/Work/Capability Agent 组合替代单一投资分析链路。

**Acceptance:** 新用户完成 Onboarding 后，在 1 分钟内看到至少一个可执行任务和完整的工作台入口，而不是空页面或资料表。

### Phase 2: Growth Execution Loop

| 顺序 | Focus | Deliverable |
|------|-------|-------------|
| 1 | Goal / Plan | 自然语言目标、AI 拆解、周期计划、里程碑和风险 |
| 2 | Task | 今日待办、进行中、完成/推迟/阻塞、目标和项目对齐 |
| 3 | Reflection | Morning、Micro Capture、Evening、提醒和补记 |
| 4 | Analysis | 执行率、目标推进率、学习投入和行为模式基础分析 |

**Acceptance:** 用户每天通过低负担输入完成工作推进和成长记录，系统能给出有依据的下一步和督促。

### Phase 3: Knowledge, Work and Capability

| 顺序 | Focus | Deliverable |
|------|-------|-------------|
| 1 | Knowledge | 内容捕获、AI 摘要、学习队列、复习和目标关联 |
| 2 | Work | 项目目录、常用软件入口、授权连接和工作事实导入 |
| 3 | Capability | Plugins、Skills、Agent 专家、启停、权限和调用记录 |
| 4 | Reports | 周报、月报、成长趋势和项目进展报告 |

**Acceptance:** 工作、学习、任务和复盘事实进入同一上下文，AI 能调用合适的能力产出结果并说明依据。

### Phase 4: Miniapp Companion and External Automation

- Miniapp 只提供一句话记录、Morning、Evening、提醒、今日任务和状态查看。
- Web 继续承载复杂 Workspace、Knowledge、Goal、Task、App、Plugin、Skill、分析和隐私管理。
- 长时间 Agent、全量外部同步和高风险本地执行在权限、审计和稳定性满足后再开放。

## Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| 每日使用负担过高 | High | High | 所有核心流程过 10 分钟测试，超时即砍字段。 |
| AI 建议泛泛 | High | High | 先做 Memory 和引用机制，再做复杂 Agent。 |
| 范围膨胀 | High | Medium | MVP 先做 Workspace、Project、Command Center、Goal/Plan/Task、Knowledge 入口和每日数据闭环；复杂同步、自动化和能力执行分期。 |
| 工作台范围过大 | High | High | 先做 Workspace、Project、Task、Goal/Plan、Knowledge、App/Skill 入口的最小闭环，复杂执行和同步分期。 |
| 能力扩展带来安全风险 | Medium | High | Plugins/Skills 必须有来源、依赖、权限、启停、Workspace 范围和 Agent Run 审计。 |
| 旧交易功能牵制新架构 | Medium | Medium | 明确旧功能降级为历史模块，不作为新主线依赖。 |
| Memory 数据质量不足 | Medium | High | 用晨间、微复盘、晚间复盘建立稳定数据入口。 |
| LLM 成本失控 | Medium | Medium | 检索优先、异步批处理、模型分层。 |
| 隐私顾虑 | Medium | High | 数据导出、删除、权限边界作为 Must Have。 |
